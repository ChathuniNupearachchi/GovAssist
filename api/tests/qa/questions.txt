# Format: one scenario per non-comment, non-blank line, grouped into
# categories via "## CATEGORY: <letter> — <name>" headers. Lines within a
# category are turns of ONE scenario unless separated by a blank line —
# multiple turns on consecutive lines (no blank line between them) are
# driven as one multi-turn conversation on a single fresh device_ref;
# a blank line starts a new scenario (and a new device_ref) within the
# same category. Edit this file freely without touching harness code —
# category letters and the two explicitly-asserted behaviors (an
# unexpected answer to a pending question re-asks it; a correction
# updates the recorded fact) are the only things the harness code itself
# depends on by name.
#
# Every category except H and J is a set of INDEPENDENT single-turn
# probes (each line is its own fresh conversation) — H and J are
# deliberately multi-turn (an interruption, or a fact then its
# correction), so their turns stay grouped without a blank line between
# them.
